Artigo científico

Vamos tratar inicialmente sobre a escrita de um artigo científico. Tendo criado o documento com base no modelo, precisamos configurá-lo conforme nossas necessidades.

Importações

Seção intitulada “Importações”

O arquivo selecionado para exibição por padrão é o article/main.typ. As primeiras linhas dele usam o comando #import para importar outros arquivos localizados na mesma pasta assets. Você pode consultar mais detalhes sobre esse comando em sua referência.

O primeiro arquivo listado é o components.typ. Ele é usado para organizar os componentes importados do modelo. Não precisa se preocupar com essa grande quantidade de linhas, nós entenderemos as funções pouco a pouco, conforme forem usadas.

Ainda nesse arquivo components.typ, você pode definir seus próprios componentes customizados para usar por todo o documento. Deixei alguns exemplos de componentes já prontos para a customização.

O componente a seguir define uma nota de editor customizada para o autor Gabriel. Veremos mais tarde como essas notas funcionam. Você pode customizar com seu próprio nome, e criar outras notas para os demais autores do artigo, e atribuir cores específicas para as notas de cada um.

Outro arquivo importado pelo main.typ é o packages.typ. Ele simplesmente separa a importação dos pacotes auxiliares que usamos no projeto. Nós usamos o pacote quati-abnt, e o pacote glossarium, que gerencia um glossário para nosso documento.

Finalmente, é importado o arquivo data/glossary.typ. A pasta data contém um conjunto de arquivos úteis para definir dados e termos comuns para todo o projeto. Esse arquivo em específico serve para definir abreviações, termos técnicos, e símbolos que devem aparecer em um glossário. Voltaremos a ele mais tarde. Por enquanto, basta saber que a lista de todos esses termos é definida com o nome glossaries_entries.

Inicialização

Seção intitulada “Inicialização”

Voltando ao arquivo main.typ, essas próximas linhas inicializam o glossário com os termos definidos previamente no arquivo data/glossary.typ. Veja que elas estão usando a variável glossaries_entries, que foi importada no topo do arquivo.

Em seguida, estão as configurações do modelo por meio das funções template. O pacote quati-abnt é modular. Ele permite utilizar e configurar separadamente as funcionalidades de: links, referências bibliográficas, notas de editor, e do artigo científico em si.

A primeira configuração é do módulo de links. O seu único parâmetro é a cor dos links pelo texto. O valor definido pela variável color_of_links é um azul escuro. Se você quiser que os links sejam da mesma cor que o texto comum, você pode definir o atributo como none. Ou, ainda, pode escolher qualquer outra cor que mais lhe agrade.

Em seguida, o documento ativa o módulo de referências bibliográficas. Esse módulo não recebe nenhuma opção de customização. Ainda assim, essa linha é importante, pois ela faz com que as referências no fim do texto sejam formatadas conforme as normas da ABNT.

Então, está disposta a inicialização do módulo de notas de editor. Elas são esses blocos de texto coloridos, que você pode usar para indicar o estado de andamento de alguma seção, ou para deixar comentários para a sua equipe.

Na inicialização, você pode customizar a família tipográfica da fonte utilizada nas notas por meio do parâmetro font_family_for_notes. Além disso, é importante que as notas não estejam visíveis na exportação do documento final. Para escondê-las, defina o atributo should_display_notes como false.

Finalmente, chegamos à inicialização do modelo de artigo científico em si. A primeira definição disponível é referente ao tamanho da fonte usada no texto. A ABNT não determina um tamanho específico, mas é usual definir como 12 pt. Por isso, a variável base_font_size já apresenta esse valor.

Em seguida, apresentam-se uma série de parâmetros que permitem mudar as famílias tipográficas usadas no texto em diferentes contextos. A ABNT não determina uma fonte específica a ser usada. Ela apenas recomenda que se use uma fonte “padrão e uniforme”. Nesse sentido, organizamos os seguintes contextos.

  • O texto comum — dos parágrafos, ilustrações, tabelas, e etc. — usa uma fonte com serifa. Por padrão, usamos a “Liberation Serif”, que busca se assemelhar à “Times New Roman”.
  • O texto de destaque — usado nos títulos — tem uma fonte sem serifa. Por padrão, usamos a “Liberation Sans”, que busca se assemelhar à “Arial”.
  • Os caracteres em ambientes de matemática usam uma fonte específica do domínio. Por padrão, usamos a “New Computer Modern Math”.
  • O texto em ambientes de código usa uma fonte monoespaçada. Por padrão usamos a “Liberation Mono”.

Para respeitar a recomendação da ABNT de um tamanho uniforme de fonte, o modelo faz o realce dos títulos usando caixa-alta, negrito, e itálico, a depender do nível. Caso você prefira usar um tamanho maior de fonte nos títulos em vez de usar caixa-alta, mude o seguinte parâmetro para true.

Por último, o parâmetro should_number_pages permite a você decidir se quer que o modelo adicione o número da página atual ao cabeçalho. Caso você esteja escrevendo um trabalho independente, é bom deixar essa opção ativa. Contudo, quando você publica um artigo para uma revista, é comum que você não numere as páginas, e deixe o editor da revista encaixar seu trabalho na melhor posição. Nesse caso, defina a opção como false.

E, para concluir a configuração do modelo, o módulo footnote formata a exibição de notas de rodapé. Ele não requer nenhum parâmetro.

Composição

Seção intitulada “Composição”

As demais linhas do arquivo main.typ organizam onde cada parte do documento será posicionada.

A parte inicial do documento contém os elementos pré-textuais, como o título, a lista de autores e o resumo. Para melhorar a organização, nós escrevemos o conteúdo dessas seções no arquivo pre_textual.typ, que está dentro da pasta content.

Então, para encaixá-las no texto, utilizamos o comando #include. Ele simplesmente copia todo o conteúdo do arquivo incluído para onde o comando foi colocado.

Inserimos, em seguida, os elementos textuais, que estão no arquivo main.typ, dentro da pasta textual, que, por sua vez, está dentro da pasta content.

Então, inserimos a seção que lista as referências bibliográficas usadas no documento. Isso é feito por meio da função #bibliography. Ela recebe como parâmetro a localização do arquivo onde estão os dados de bibliografia no formato BibTeX.

Finalmente, inserimos os elementos pós-textuais, que estão no arquivo post_textual.typ dentro da pasta content.

Dados

Seção intitulada “Dados”

O primeiro passo para configurar o modelo conforme as suas necessidades é editar o arquivo data.typ, que fica dentro da pasta data. Ele guarda os dados do artigo e de seus autores.

Sua primeira variável é chamada title, e define o título do trabalho. Edite o conteúdo dentro dos colchetes ([...]) conforme o título do seu artigo.

A próxima variável é a subtitle, que define um subtítulo para o trabalho. Essa variável é opcional. Se você escrever um subtítulo, ele aparecerá separado do título pelo símbolo de dois-pontos (:). Além disso, o título principal ganha um destaque em negrito, enquanto o subtítulo permanece como texto comum. Caso você não queira especificar um subtítulo, apenas remova o bloco de texto cercado por colchetes ([...]).

A última variável de dados é a lista de autores, denominada authors.

Cada item da lista é um dicionário, que define as seguintes informações.

  • O primeiro nome é definido pelo atributo first_name.
    • Caso o autor tenha um nome composto — como Ana Maria —, ambos os nomes devem ser registrados aqui.
  • O atributo last_name especifica o último sobrenome do autor.
    • Este é o sobrenome destacado em caixa-alta nas referências. Portanto, apenas um deve ser fornecido.
  • Então, os demais sobrenomes devem ser especificados pelo atributo middle_name.
    • Caso não haja mais sobrenomes, use o valor none.
  • O gênero do autor pode ser especificado pelo atributo gender.
    • Ele aceita o valor "f" para feminino e "m" para masculino.
  • O atributo curriculum define a instituição do autor, e seu e-mail de contato.
